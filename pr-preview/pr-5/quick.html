1 Quick Start🔗

Parsing happens in two steps. First a Parser turns a string into an AST. The AST is a tree that records how the grammar matched the input. Then an ordinary recursive function turns the AST into the data the program needs.

Take numbers such as "0", "-7", and "140". A number is an optional minus sign followed by either a lone zero or a non-zero digit and any number of further digits:

(require parser-combinator/parse)
 
; Parser
(define-parser NONZERO-DIGIT
  (alt* (lit "1") (lit "2") (lit "3") (lit "4") (lit "5")
        (lit "6") (lit "7") (lit "8") (lit "9")))
 
; Parser
(define-parser DIGIT
  (alt (lit "0") NONZERO-DIGIT))
 
; Parser
(define-parser NUMBER
  (seq* 'number
        (opt (lit "-"))
        (alt (lit "0")
             (seq 'digits
                  NONZERO-DIGIT
                  (star DIGIT)))))

Running a parser with parse produces the AST:

> (parse NUMBER "-7")

(seq-node

 'number

 (lit-node "-")

 (seq-node 'digits (lit-node "7") (emp-node)))

A number does not need the structure of its AST. The function flatten-ast gets back the text that matched. Then string->number reads it:

; String -> Number
; parses str as a number
> (define (string->number* str)
    (string->number (flatten-ast (parse NUMBER str))))
> (string->number* "0")

0

> (string->number* "-7")

-7

> (string->number* "140")

140

Input that is not in the grammar is an error:

> (string->number* "007")

bad input, had leftover text "07"

Most grammars need more than flatten-ast. They need a real function from ASTs to data. Design it with the design recipe so that it follows the structure of the grammar. The source of parser-combinator/json is a complete example.
