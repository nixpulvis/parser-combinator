2 Parsers and Combinators🔗

 (require parser-combinator/parse)
  package: parser-combinator

2.1 Data Definitions🔗

The library works with three kinds of data. Each one comes with a data definition, and the signatures below refer to them by name.

AST : (or/c emp-node? lit-node? wrap-node? seq-node?)

An AST is one of:

  • (emp-node), for input that matched without consuming any text

  • (lit-node string), for a piece of text that a primitive parser matched

  • (wrap-node label ast), for a delimited AST, such as the contents of a pair of brackets

  • (seq-node label left right), for two ASTs that matched one after the other

The grammar chooses the labels, which are symbols. They let the program that consumes an AST tell the different kinds of sequences apart.

Result : (or/c 'error result?)

A Result is one of:

  • 'error, meaning the parser did not match

  • (result ast remaining), meaning the parser matched a prefix of its input, producing ast, and left the string remaining unconsumed

Parser : (-> string? (or/c 'error result?))

A Parser is a function that consumes a string and produces a Result. A parser only ever matches a prefix of its input. It is up to parse to insist that a match covers the whole string.

Because parsers are plain functions, the parsers in this library can be applied directly, which is handy for testing and at the REPL:

Examples:
> ((lit "hi") "high")

(result (lit-node "hi") "gh")

> ((lit "hi") "bye")

'error

struct

(struct emp-node ()
    #:transparent)
represents a match that consumed no input, as produced by emp, by opt when its parser fails, and at the end of every star or plus repetition.

struct

(struct lit-node (value)
    #:transparent)
  value : string?
represents the matched text value, as produced by lit and by rx.

struct

(struct wrap-node (label value)
    #:transparent)
  label : symbol?
  value : AST
represents the AST value found between two delimiters, as produced by wrap, which supplies the label.

struct

(struct seq-node (label left right)
    #:transparent)
  label : symbol?
  left : AST
  right : AST
represents the AST left followed by the AST right, as produced by seq and seq*, which supply the label, and by star and plus, which use the label 'rep.

struct

(struct result (node remaining)
    #:transparent)
  node : AST
  remaining : string?
represents a successful match, as produced by any Parser that matches. See Result.

This structure is exported so that programs can write their own parsers, but it may be hidden in a future version.

2.2 Defining Parsers🔗

syntax

(define-parser id parser-expr)

defines id as a Parser that behaves like parser-expr.

Unlike define, define-parser does not evaluate parser-expr until id is applied to a string. This delay lets a parser refer to itself, or to parsers defined further down in the module, which is what most grammars need. The definition

(define-parser id parser-expr)

is equivalent to

(define (id s) (parser-expr s))

so parser-expr is evaluated again every time the parser runs.

Examples:
; Parser
; matches balanced parentheses, such as "(()())"
> (define-parser PARENS
    (star (seq 'parens (lit "(") (seq 'close PARENS (lit ")")))))
> (flatten-ast (parse PARENS "(()())"))

"(()())"

> (parse PARENS "(()")

bad input, had leftover text "(()"

2.3 Primitive Parsers🔗

procedure

(lit str) → Parser

  str : string?
produces a Parser that matches the text str at the start of its input. The AST is (lit-node str).

Examples:
> ((lit "-") "-1.35")

(result (lit-node "-") "1.35")

> ((lit "hi") "high")

(result (lit-node "hi") "gh")

> ((lit "high") "hi")

'error

> ((lit "") "walrus")

(result (lit-node "") "walrus")

procedure

(rx pattern) → Parser

  pattern : regexp?
produces a Parser that matches pattern at the start of its input. A match later in the input does not count. The AST is a lit-node holding the matched text. pattern may be a regexp or a pregexp, such as #rx"[^ab]" or #px"\\d+".

Examples:
> ((rx #rx"[^ab]") "cab")

(result (lit-node "c") "ab")

> ((rx #rx"[^ab]") "bad")

'error

> ((rx #px"\\d+") "42x")

(result (lit-node "42") "x")

> ((rx #rx"a|b") "xb")

'error

procedure

(emp) → Parser

produces a Parser that always succeeds without consuming any input. The AST is (emp-node).

Note that emp is a function that produces a parser, not a parser itself, so it is used as (emp).

Example:
> ((emp) "abc")

(result (emp-node) "abc")

2.4 Combinators🔗

procedure

(alt p1 p2) → Parser

  p1 : Parser
  p2 : Parser
produces a Parser that tries p1 and, only if it fails, tries p2 on the same input.

Examples:
> ((alt (lit "a") (lit "b")) "bc")

(result (lit-node "b") "c")

> ((alt (lit "a") (lit "b")) "c")

'error

The choice is ordered and final: once p1 matches, alt never goes back to try p2, even if the rest of the grammar then fails. When one alternative is a prefix of another, list the longer one first.

Examples:
> (parse (seq 'x (alt (lit "a") (lit "ab")) (lit "c")) "abc")

bad input, got error

> (parse (seq 'x (alt (lit "ab") (lit "a")) (lit "c")) "abc")

(seq-node 'x (lit-node "ab") (lit-node "c"))

procedure

(alt* p ...+) → Parser

  p : Parser
produces a Parser that tries each p in order and behaves like the first one that matches. It is the same as nesting alt to the right, and with a single parser (alt* p) is the same as p.

Example:
> ((alt* (lit "x") (lit "y") (lit "z")) "zebra")

(result (lit-node "z") "ebra")

procedure

(seq label p1 p2) → Parser

  label : symbol?
  p1 : Parser
  p2 : Parser
produces a Parser that runs p1 and then runs p2 on the input that p1 left over. It fails if either parser does. The AST is (seq-node label left right), where left and right are the ASTs of p1 and p2.

Examples:
> ((seq 'pair (lit "a") (lit "b")) "abc")

(result (seq-node 'pair (lit-node "a") (lit-node "b")) "c")

> ((seq 'pair (lit "a") (lit "b")) "acb")

'error

procedure

(seq* label p ...+) → Parser

  label : symbol?
  p : Parser
produces a Parser that runs each p in order. It is the same as nesting seq to the right, using label for every seq-node. With a single parser, (seq* label p) is the same as p.

Example:
> (parse (seq* 'abc (lit "a") (lit "b") (lit "c")) "abc")

(seq-node 'abc (lit-node "a") (seq-node 'abc (lit-node "b") (lit-node "c")))

procedure

(opt p) → Parser

  p : Parser
produces a Parser that behaves like p if p matches, and otherwise succeeds without consuming input, producing (emp-node).

Examples:
> ((opt (lit "-")) "-5")

(result (lit-node "-") "5")

> ((opt (lit "-")) "5")

(result (emp-node) "5")

procedure

(star p) → Parser

  p : Parser
produces a Parser that matches p zero or more times, as many times as possible. The AST is a chain of seq-nodes labeled 'rep, one per match, ending in (emp-node):

(seq-node 'rep ast_1 (seq-node 'rep ast_2 ... (emp-node)))

Use star-foldr or star-foldl to process such a chain.

Examples:
> ((star (lit "a")) "aab")

(result

 (seq-node 'rep (lit-node "a") (seq-node 'rep (lit-node "a") (emp-node)))

 "b")

> ((star (lit "a")) "b")

(result (emp-node) "b")

Like alt, star never gives back a match, so (seq 'x (star (lit "a")) (lit "a")) matches nothing at all. A parser p that can succeed without consuming input, such as (opt q), makes (star p) loop forever on any input where p matches the empty string.

procedure

(plus p) → Parser

  p : Parser
produces a Parser that matches p one or more times. The AST has the same shape as for star.

Examples:
> (parse (plus (lit "a")) "aa")

(seq-node 'rep (lit-node "a") (seq-node 'rep (lit-node "a") (emp-node)))

> (parse (plus (lit "a")) "")

bad input, got error

procedure

(wrap label left body right) → Parser

  label : symbol?
  left : Parser
  body : Parser
  right : Parser
produces a Parser that runs left, body, and right in order, keeping only the AST of body. The AST is (wrap-node label body-ast).

Example:
> (parse (wrap 'parens (lit "(") (lit "x") (lit ")")) "(x)")

(wrap-node 'parens (lit-node "x"))

procedure

(unwrap left body right) → Parser

  left : Parser
  body : Parser
  right : Parser
is like wrap, but produces the AST of body itself. It is useful for skipping over text that the program does not care about, such as whitespace.

Examples:
> (define SPACES (star (lit " ")))
> (parse (unwrap SPACES (lit "x") SPACES) "  x ")

(lit-node "x")

2.5 Running Parsers🔗

procedure

(parse p str) → AST

  p : Parser
  str : string?
applies p to str and produces the resulting AST. Unlike applying p directly, parse demands that p consume all of str. It raises exn:fail if p fails or leaves text over.

Examples:
> (parse (lit "hi") "hi")

(lit-node "hi")

> (parse (lit "hi") "bye")

bad input, got error

> (parse (lit "hi") "high")

bad input, had leftover text "gh"

2.6 Consuming ASTs🔗

procedure

(flatten-ast ast) → string?

  ast : AST
produces the text that ast matched, by appending the strings in all of its lit-nodes from left to right. Delimiters dropped by wrap and unwrap are not part of the result.

Examples:
> (flatten-ast (parse (seq* 'abc (lit "a") (lit "b") (lit "c")) "abc"))

"abc"

> (flatten-ast (parse (wrap 'parens (lit "(") (lit "x") (lit ")")) "(x)"))

"x"

procedure

(star-foldr op base ast) → any/c

  op : (-> AST any/c any/c)
  base : any/c
  ast : AST
folds op over the ASTs in a repetition chain, as produced by star or plus, from right to left, like foldr on lists. If ast is not a 'rep seq-node, for example when star matched zero times, the result is base.

Example:
> (star-foldr (lambda (a acc) (cons (flatten-ast a) acc))
              '()
              (parse (star (alt (lit "a") (lit "b"))) "aab"))

'("a" "a" "b")

procedure

(star-foldl op base ast) → any/c

  op : (-> AST any/c any/c)
  base : any/c
  ast : AST
is like star-foldr, but folds from left to right, like foldl on lists.

Example:
> (star-foldl (lambda (a acc) (cons (flatten-ast a) acc))
              '()
              (parse (star (alt (lit "a") (lit "b"))) "aab"))

'("b" "a" "a")
