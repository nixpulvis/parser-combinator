3 JSON🔗

 (require parser-combinator/json)
  package: parser-combinator

This library parses text in the JSON data exchange format, as described on the JSON web site, into Racket values. It is written entirely with parser-combinator/parse, so its source is also a worked example of a complete grammar.

3.1 JSON Values🔗

JSON : any/c

A JSON is one of:

  • a string?, for a JSON string

  • an exact number?, for a JSON number

  • a boolean?, for true and false

  • 'null, for null

  • a (listof JSON), for a JSON array, an ordered collection of values

  • a (listof json-pair?), for a JSON object, a collection of named values

Note that an empty JSON array and an empty JSON object are both represented as '().

struct

(struct json-pair (name value)
    #:transparent)
  name : string?
  value : JSON
represents one named value in a JSON object, as produced by string->json and parse-json-pair for each name and value in the object. The pairs of an object appear in the same order as in the text.

procedure

(string->json str) → JSON

  str : string?
parses str as a JSON value, ignoring whitespace around it. It raises exn:fail if str is not valid JSON.

Examples:
> (string->json "[]")

'()

> (string->json "-1.5e3")

-1500

> (string->json "[1, {\"foo\": false}, null]")

(list 1 (list (json-pair "foo" #f)) 'null)

> (string->json "[1, 2")

bad input, got error

Strings are produced as they appear in the text: escape sequences such as \n are not decoded.

Example:
> (string->json "\"a\\nb\"")

"a\\nb"

3.2 Grammar🔗

The grammar behind string->json is made of the parsers below: a few small ones for single characters, then one per kind of JSON value. They are exported so that each part of the grammar can be tested on its own, and they may be hidden in a future version.

Wherever the grammar allows whitespace around a value or a punctuation mark, the parsers skip any number of SPACEs with unwrap, so whitespace never appears in an AST.

value

SPACE : Parser

matches one whitespace character: a space, a tab, a newline or a carriage return. The AST is a lit-node holding the character.

Example:
> ((star SPACE) " \t\nx")

(result

 (seq-node

  'rep

  (lit-node " ")

  (seq-node 'rep (lit-node "\t") (seq-node 'rep (lit-node "\n") (emp-node))))

 "x")

value

DIGIT+ : Parser

matches one non-zero digit, 1 through 9. Despite its name, it matches a single digit, not one or more. The AST is a lit-node holding the digit.

Examples:
> (parse DIGIT+ "7")

(lit-node "7")

> (parse DIGIT+ "0")

bad input, got error

value

DIGIT : Parser

matches one digit, 0 through 9, using DIGIT+ for the non-zero ones. The AST is a lit-node holding the digit.

Example:
> (parse DIGIT "0")

(lit-node "0")

value

HEXIT : Parser

matches one hexadecimal digit: a DIGIT, or a letter from a through f in either case. The AST is a lit-node holding the character.

Example:
> (parse HEXIT "F")

(lit-node "F")

value

STRING : Parser

matches a JSON string, including its quotes. Inside the quotes it accepts any character other than \, " and the control characters U+0000 through U+001F, and the escape sequences \", \\, \/, \b, \f, \n, \r, \t, and \u followed by four HEXITs.

The AST is (wrap-node 'string chain), where chain is the star repetition of the characters and escapes between the quotes.

Examples:
> (parse STRING "\"hi\"")

(wrap-node

 'string

 (seq-node 'rep (lit-node "h") (seq-node 'rep (lit-node "i") (emp-node))))

> (parse STRING "\"a\tb\"")

bad input, got error

value

NUMBER : Parser

matches a JSON number: an optional -, then either 0 or a DIGIT+ followed by any number of DIGITs, then an optional fraction, then an optional exponent. The fraction is a . followed by one or more DIGITs. The exponent is an e or E, an optional + or -, and one or more DIGITs.

The AST is a chain of seq-nodes labeled 'number that holds the four parts in order, with (emp-node) for each optional part that is missing:

(seq-node 'number sign
  (seq-node 'number integer
    (seq-node 'number fraction exponent)))

The integer is (lit-node "0") or a seq-node labeled 'significand. A fraction is labeled 'decimal and an exponent is labeled 'exponent.

Examples:
> (parse NUMBER "7")

(seq-node

 'number

 (emp-node)

 (seq-node

  'number

  (seq-node 'significand (lit-node "7") (emp-node))

  (seq-node 'number (emp-node) (emp-node))))

> (parse NUMBER "1.")

bad input, had leftover text "."

value

PAIR : Parser

matches one name and value in a JSON object, such as "name": true. The AST is

(seq-node 'pair name (seq-node 'pair (lit-node ":") value))

where name is the AST of STRING and value is the AST of VALUE.

Example:
> (parse PAIR "\"a\": true")

(seq-node

 'pair

 (wrap-node 'string (seq-node 'rep (lit-node "a") (emp-node)))

 (seq-node 'pair (lit-node ":") (lit-node "true")))

value

OBJECT : Parser

matches a JSON object, that is, zero or more PAIRs separated by commas and surrounded by braces. The AST is (wrap-node 'object body). For an empty object the body is (emp-node), and otherwise it is

(seq-node 'object-first pair rest)

where pair is the first pair and rest is a star repetition with one (seq-node 'object-rest (lit-node ",") pair) for each further pair.

Example:
> (parse OBJECT "{}")

(wrap-node 'object (emp-node))

value

ARRAY : Parser

matches a JSON array, that is, zero or more VALUEs separated by commas and surrounded by brackets. The AST has the same shape as for OBJECT, with the labels 'array, 'array-first and 'array-rest.

Example:
> (parse ARRAY "[true, false]")

(wrap-node

 'array

 (seq-node

  'array-first

  (lit-node "true")

  (seq-node

   'rep

   (seq-node 'array-rest (lit-node ",") (lit-node "false"))

   (emp-node))))

value

VALUE : Parser

matches any JSON value, along with the whitespace around it. The AST is that of STRING, NUMBER, OBJECT or ARRAY, or a lit-node holding "true", "false" or "null".

Example:
> (parse VALUE "  null ")

(lit-node "null")

3.3 Converting ASTs🔗

Each of these functions consumes the AST of one of the parsers above and produces the matching JSON. Together they are the second half of string->json, which is the same as

(parse-json-value (parse VALUE str))

Like the grammar, these functions are exported for testing, and they may be hidden in a future version.

procedure

(parse-json-value ast) → JSON

  ast : AST
converts the AST of VALUE, passing it to one of the functions below based on its node type and label. It raises exn:fail if ast is not an AST that VALUE produces.

Example:
> (parse-json-value (parse VALUE "[1, true]"))

'(1 #t)

procedure

(parse-json-string ast) → string?

  ast : AST
converts the AST of STRING, using flatten-ast. The quotes are dropped and escape sequences are left as they are.

Example:
> (parse-json-string (parse STRING "\"hi\""))

"hi"

procedure

(parse-json-number ast) → number?

  ast : AST
converts the AST of NUMBER to an exact number.

Example:
> (parse-json-number (parse NUMBER "-1.5"))

-3/2

procedure

(parse-json-pair ast) → json-pair?

  ast : AST
converts the AST of PAIR.

Example:
> (parse-json-pair (parse PAIR "\"a\": true"))

(json-pair "a" #t)

procedure

(parse-json-object ast) → (listof json-pair?)

  ast : AST
converts the AST of OBJECT to a list of pairs, in order. It raises exn:fail if ast does not have that shape.

Example:
> (parse-json-object (parse OBJECT "{\"a\": 1, \"b\": 2}"))

(list (json-pair "a" 1) (json-pair "b" 2))

procedure

(parse-json-array ast) → (listof JSON)

  ast : AST
converts the AST of ARRAY to a list of values, in order. It raises exn:fail if ast does not have that shape.

Example:
> (parse-json-array (parse ARRAY "[1, 2, 3]"))

'(1 2 3)
