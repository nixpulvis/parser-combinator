2 Parsers and Combinators🔗

 (require parser-combinator/parse)
  package: parser-combinator

procedure

(parse p in) → Value

  p : Parser
  in : input?
applies Parser p to the Input in and produces the resulting Value. Unlike applying p directly, parse demands that p consume all of in. It raises exn:fail if p fails or leaves text over, saying what it found where the parse got furthest, by line and column: the furthest that any parser failed at, or that p’s match ended at. After that, the error may say more, a field to a line:

  • lexing: where no token begins, over what a lexer made, the kind of token whose rule got furthest into the text there. The error is where that rule got to, rather than where the token would begin. The grammar has no part in what a token is, so then this is the only field.

  • expected: what would have matched where the parse got furthest: the text of a lit, a character of a span given a string, the kind of a tok, the end of input, or the name of a named parser that would have begun there, rather than what’s in it. Parsers given a predicate or a Run, rx, and where don’t say what they expect.

  • in: the innermost parser named with define-parser, or with parser and a name, that the parse got furthest inside, having begun before it.

To find what was expected, and where, parse runs p again over the same input, so the functions given to pmap run twice for a parse that fails.

Examples:
> (parse (lit "hi") "hi")

"hi"

> (parse (lit "hi") "bye")

parse: unexpected text "bye" at line 1, column 1

  expected: "hi"

> (parse (lit "hi") "high")

parse: unexpected text "gh" at line 1, column 3

  expected: end of input

> (define-parser GREETING
    (seq (lit "hi ") (alt (lit "you") (lit "all"))))
> (parse GREETING "hi yall")

parse: unexpected text "all" at line 1, column 5

  expected: "you"

  in: GREETING

2.1 Data Definitions🔗

Value : any/c

A Value is whatever a Parser produces when it matches. The parsers in this library produce plain Racket values:

  • emp produces the Value it’s given, or '()

  • lit, rx, and span produce the matched text, a string

  • skip produces '()

  • pmap produces whatever its function returns, given its parsers’ Values

  • seq produces the list of its parsers’ Values

  • alt produces the Value of the parser that matched

  • opt produces its parser’s Value, or its default if its parser fails

  • star and plus produce the list of their parser’s Values

  • where produces its parser’s Value, when its condition is met

  • unwrap produces the Value of its middle parser

  • preceded and terminated produce the Value of the parser they don’t skip

  • sep-by* and sep-by+ produce the list of their parser’s Values, without the separators’

The functions given to pmap are where a grammar builds the data the program needs, such as a number, or a structure of its own.

Result : (or/c 'error result?)

A Result is one of:

  • 'error, meaning the parser did not match

  • (result value remaining), meaning the parser matched a prefix of its input, producing value, and left the rest of it, the Input remaining, unconsumed. It’s a string when the input was a string, and otherwise what a lexer would make of the rest.

Parser : parser?

A Parser is made by the combinators below, or by parser from a Run (see Run Parsers). A combinator given anything else raises exn:fail:contract when it makes its parser. A parser only ever matches a prefix of its input. It is up to parse to insist that a match covers the whole input.

Parsers are functions. A parser can be applied directly to an Input, such as a string, producing a Result:

Examples:
> ((lit "hi") "high")

(result "hi" "gh")

> ((lit "hi") "bye")

'error

The parsers pass positions in the input to one another rather than copying it, so applying a parser copies the input only once, for the remaining of its Result.

struct

(struct result (value remaining)
    #:transparent)
  value : Value
  remaining : input?
represents a successful match, as produced by any Parser that matches. See Result.

Input : input?

An Input is the text a parser matches: a string, or what a lexer makes from one, such as json-lexer, which also splits the text into tokens for a grammar over tokens. Parsers over characters, like lit, match the text of either. Only a grammar over tokens needs a lexer’s.

procedure

(input? v) → boolean?

  v : any/c
returns #t if v is an Input: a string, or what a lexer makes.

2.2 Defining Parsers🔗

syntax

(define-parser id parser-expr)

defines id as a Parser that behaves like parser-expr.

Unlike define, define-parser does not evaluate parser-expr until id is first applied to a string. This lets a parser refer to itself. It can also refer to parsers that are defined later in the module. After that first application, id keeps the parser that parser-expr produced, so parser-expr is evaluated only once, rather than every time the parser runs.

The parser’s object-name is id, so it prints with that name, and parse’s error names it when the parse fails inside it.

Examples:
; Parser
; matches balanced parentheses, such as "(()())",
; producing a list for each pair
> (define-parser PARENS
    (star (unwrap (lit "(") PARENS (lit ")"))))
> (parse PARENS "(()())")

'((() ()))

> (parse PARENS "(()")

parse: unexpected end of input at line 1, column 4

  expected: "(" or ")"

  in: PARENS

> PARENS

#<procedure:PARENS>

2.3 Primitive Parsers🔗

procedure

(emp [v]) → Parser

  v : any/c = '()
produces a Parser that always succeeds without consuming any input. The Value is v.

Note that emp is a function that produces a parser, not a parser itself, so it is used as (emp).

Examples:
> ((emp) "abc")

(result '() "abc")

> ((emp 0) "abc")

(result 0 "abc")

procedure

(lit str) → Parser

  str : string?
produces a Parser that matches the text str at the start of its input. The Value is str.

Examples:
> ((lit "-") "-1.35")

(result "-" "1.35")

> ((lit "hi") "high")

(result "hi" "gh")

> ((lit "high") "hi")

'error

> ((lit "") "walrus")

(result "" "walrus")

procedure

(rx pattern) → Parser

  pattern : regexp?
produces a Parser that matches pattern at the start of its input. A match later in the input does not count. The Value is the matched text. pattern may be a regexp or a pregexp, such as #rx"[^ab]" or #px"\\d+".

Examples:
> ((rx #rx"[^ab]") "cab")

(result "c" "ab")

> ((rx #rx"[^ab]") "bad")

'error

> ((rx #px"\\d+") "42x")

(result "42" "x")

> ((rx #rx"a|b") "xb")

'error

procedure

(span ok?) → Parser

  ok? : (or/c (-> char? any/c) string?)
produces a Parser that matches the longest run of one or more characters at the start of its input that ok? accepts. It fails if the first character isn’t accepted, or if there is no input left. The Value is the matched text. In place of a function, ok? can be a string of the characters to accept.

Examples:
> ((span char-alphabetic?) "abc123")

(result "abc" "123")

> ((span char-numeric?) "abc")

'error

> ((span "01") "0110 2")

(result "0110" " 2")

A span matches the same text as an rx for a character class, such as (rx #rx"[a-z]+"), but costs less when the runs are short. Matching a regexp against a string has a cost every time, even when it matches one character or none, and span only checks characters. Because it always takes the longest run, it can’t match a fixed number of characters, which takes an rx such as (rx #px"[0-9]{4}").

procedure

(skip ok?) → Parser

  ok? : (or/c (-> char? any/c) string?)
produces a Parser that matches the longest run of zero or more characters at the start of its input that ok? accepts, with ok? as for span. It always succeeds, and the Value is '(). It is for text that a grammar passes over, such as whitespace.

Examples:
> ((skip " \t") "  \tx")

(result '() "x")

> ((skip " \t") "x")

(result '() "x")

It matches what (pmap (lambda (_) '()) (opt (span ok?))) does, without copying the text it skips.

2.4 Combinators🔗

procedure

(pmap f p ...+) → Parser

  f : procedure?
  p : Parser
produces a Parser that runs each p in order, each on the input that the previous one left over. If any p fails, the parser fails. The Value is the result of calling f with the Values of the ps, one argument per parser, in order, as map calls its function with one element of each list.

With one p, f converts its Value, and with more, f combines theirs. It can ignore any of them, which is useful for dropping delimiters. For the common cases, see unwrap, preceded, and terminated.

Examples:
> ((pmap string->number (rx #px"\\d+")) "42!")

(result 42 "!")

> ((pmap length (star (lit "a"))) "aab")

(result 2 "b")

> ((pmap string-append (lit "a") (lit "b")) "abc")

(result "ab" "c")

> ((pmap string-append (lit "a") (lit "b")) "acb")

'error

> (parse (pmap (lambda (l x r) (string->symbol x))
               (lit "(") (rx #rx"[a-z]+") (lit ")"))
         "(abc)")

'abc

f must accept as many arguments as there are ps. If it does not, pmap raises exn:fail:contract when it makes the parser, before any input is parsed.

Example:
> (pmap (lambda (a b) a) (lit "a") (lit "b") (lit "c"))

pmap: contract violation

  expected: (procedure-arity-includes/c 3)

  given: #<procedure>

procedure

(seq p ...+) → Parser

  p : Parser
produces a Parser that runs each p in order. The Value is the list of the ps’ Values, in order. It is the same as (pmap list p ...).

Examples:
> ((seq (lit "a") (lit "b")) "abc")

(result '("a" "b") "c")

> ((seq (lit "a") (lit "b")) "acb")

'error

procedure

(alt p ...) → Parser

  p : Parser
produces a Parser that tries each p in order, on the same input, and behaves like the first one that matches. If none of them matches, it fails, so with no parsers it always fails.

Examples:
> ((alt (lit "a") (lit "b")) "bc")

(result "b" "c")

> ((alt (lit "a") (lit "b")) "c")

'error

> ((alt (lit "x") (lit "y") (lit "z")) "zebra")

(result "z" "ebra")

The choice is ordered and final: once a p matches, alt never goes back to try the ones after it, even if the rest of the grammar then fails. When one alternative is a prefix of another, list the longer one first.

Examples:
> (parse (seq (alt (lit "a") (lit "ab")) (lit "c"))
         "abc")

parse: unexpected text "bc" at line 1, column 2

  expected: "c"

> (parse (seq (alt (lit "ab") (lit "a")) (lit "c"))
         "abc")

'("ab" "c")

alt looks at the next character of its input, and skips the alternatives whose matches can’t start with it. When each alternative starts with its own characters, for example the kinds of value in JSON, only one of them runs, however many there are. This never changes what alt matches, only how many alternatives it tries.

alt can only skip an alternative when it knows which characters the alternative starts with. A lit starts with the first character of its string, and a span or skip given a string starts with any character in that string. A parser built with the combinators starts like the parsers inside it, so (seq (lit "-") p) starts with #\-, and (alt (lit "a") (lit "b")) with #\a or #\b.

Any other parser could start with any character, so alt always tries it. That covers an rx, a span or skip given a function, and a parser made with parser. It also covers a parser built with one of them at its start, such as (seq (rx #px"\\d") p).

procedure

(opt p [default]) → Parser

  p : Parser
  default : any/c = '()
produces a Parser that behaves like p if p matches, and otherwise succeeds without consuming input, producing default. It is the same as (alt p (emp default)).

Examples:
> ((opt (lit "-")) "-5")

(result "-" "5")

> ((opt (lit "-")) "5")

(result '() "5")

> ((opt (lit "-") "+") "5")

(result "+" "5")

procedure

(star p) → Parser

  p : Parser
produces a Parser that matches p zero or more times, as many times as possible. The Value is the list of the Values of the matches, in order.

Examples:
> ((star (lit "a")) "aab")

(result '("a" "a") "b")

> ((star (lit "a")) "b")

(result '() "b")

Like alt’s choice, the matches are final: star takes as many as it can, and never goes back to take fewer, even if the rest of the grammar then fails. So (seq (star (lit "a")) (lit "a")) matches nothing at all, because the star leaves no "a" for the lit.

star stops at the first match of p that consumes no input, leaving that match out, so a p that can match the empty string, such as (opt q), can’t make it repeat forever.

Example:
> ((star (opt (lit "a"))) "aab")

(result '("a" "a") "b")

procedure

(plus p) → Parser

  p : Parser
produces a Parser that matches p one or more times. The Value is the list of the Values of the matches, as for star.

Examples:
> (parse (plus (lit "a")) "aa")

'("a" "a")

> (parse (plus (lit "a")) "")

parse: unexpected end of input at line 1, column 1

  expected: "a"

procedure

(where ok? p) → Parser

  ok? : (-> Value any/c)
  p : Parser
produces a Parser that matches what p matches, but only when ok? accepts its Value. Otherwise it fails where p began, so a parse that fails there says what p matched. The Value is p’s.

Examples:
> (define NUMBER (pmap string->number (rx #px"\\d+")))
> (define BYTE (where byte? NUMBER))
> (parse BYTE "200")

200

> (parse (seq (lit "x=") BYTE) "x=300")

parse: unexpected text "300" at line 1, column 3

procedure

(unwrap left body right) → Parser

  left : Parser
  body : Parser
  right : Parser
produces a Parser that runs left, body, and right in order, and produces the Value of body. It is the same as (pmap (lambda (l b r) b) left body right), and is useful for skipping over text that the program does not care about, such as whitespace.

Examples:
> (define SPACES (skip " "))
> (parse (unwrap SPACES (lit "x") SPACES) "  x ")

"x"

procedure

(preceded skipped p) → Parser

  skipped : Parser
  p : Parser
produces a Parser that runs skipped and then p, and produces the Value of p. It is the same as (pmap (lambda (_ v) v) skipped p), and is useful for dropping punctuation in front of a value.

Example:
> (parse (preceded (lit "$") (rx #px"\\d+")) "$42")

"42"

procedure

(terminated p skipped) → Parser

  p : Parser
  skipped : Parser
produces a Parser that runs p and then skipped, and produces the Value of p. It is the same as (pmap (lambda (v _) v) p skipped).

Example:
> (parse (terminated (rx #px"\\d+") (lit "%")) "42%")

"42"

procedure

(sep-by* p sep) → Parser

  p : Parser
  sep : Parser
produces a Parser that matches p zero or more times, with a sep between each match. The Value is the list of the Values of p’s matches, in order, without sep’s. It is the same as (opt (sep-by+ p sep)), so unlike sep-by+, it matches the empty string, producing '().

Examples:
> (define DIGITS (rx #px"\\d+"))
> (parse (sep-by* DIGITS (lit ",")) "1,22,333")

'("1" "22" "333")

> (parse (sep-by* DIGITS (lit ",")) "")

'()

> (parse (sep-by+ DIGITS (lit ",")) "")

parse: unexpected end of input at line 1, column 1

A sep is only matched along with the p after it, so a trailing sep is left unconsumed.

Example:
> ((sep-by* DIGITS (lit ",")) "1,22,")

(result '("1" "22") ",")

procedure

(sep-by+ p sep) → Parser

  p : Parser
  sep : Parser
produces a Parser that matches p one or more times, with a sep between each match, as sep-by* does. It is the same as (pmap cons p (star (preceded sep p))).

Examples:
> (parse (sep-by+ DIGITS (lit ",")) "1,22")

'("1" "22")

> (parse (sep-by+ DIGITS (lit ",")) "1")

'("1")

2.5 Run Parsers🔗

 (require (submod parser-combinator/parse positions))
  package: parser-combinator

Every Parser is made by the combinators in parser-combinator/parse, or by parser, from this module, out of a Run written by hand. Prefer the combinators. They know which characters, or tokens, each parser can begin with, so alt skips the alternatives that can’t match, and they record where they fail, for parse’s error. Write a Run for what the combinators can’t say, such as a fixed number of characters, a grammar that depends on what it has already matched, or a loop over characters that has to be fast.

A Run is given an Input and a position in its text, and matches from that position. The combinators call one another’s Runs with positions, rather than copying the input, and a Run written by hand does the same. One that follows these rules works as the combinators do, in any grammar:

  • It reads the text with input-text. The Input it’s given needn’t be the string being parsed, so it doesn’t use the Input as a string.

  • It produces (matched value end), where end is the position just after its match, or 'error.

  • It runs other parsers with run, passing its own Input and a position, so they work over tokens as well as characters.

  • Where the text is wrong, it fails with fail, at the position of what’s wrong, so parse’s error points there. A Run that produces 'error instead fails where it began.

alt can’t tell what a Run begins with, so it always tries one. When its matches all begin with the same text, match that text with a lit first, and write a Run for the rest.

Match : (or/c 'error matched?)

A Match is one of:

  • 'error, meaning the parser did not match

  • (matched value end), meaning the parser matched, producing value, and the match ended just before position end of the input’s text

Run : (-> input? exact-nonnegative-integer? (or/c 'error matched?))

A Run matches its input’s text starting at the given position, and produces a Match.

struct

(struct matched (value end)
    #:transparent)
  value : Value
  end : exact-nonnegative-integer?
represents a successful match, as produced by a Run that matches. See Match.

syntax

(parser run-expr)

(parser run-expr name-expr)
 
  run-expr : Run
  name-expr : (or/c symbol? #f)
makes a Parser from a Run. Applying it to a string calls its Run from position 0, and turns the Match into a Result, copying the rest of the input once, for its remaining. The combinators in parser-combinator/parse call its Run directly, with positions, so used inside a grammar it never copies.

Examples:
; Char-Predicate -> Parser
; matches one character that `ok?` accepts
> (define (char-where ok?)
    (parser
     (lambda (in i)
       (define s (input-text in))
       (if (and (< i (string-length s))
                (ok? (string-ref s i)))
           (matched (string (string-ref s i)) (add1 i))
           'error))))
> (parse (plus (char-where char-alphabetic?)) "abc")

'("a" "b" "c")

> ((char-where char-numeric?) "7up")

(result "7" "up")

The value of name-expr is the parser’s object-name, so the parser prints with that name, and parse’s error names it when the parse fails inside it, as it does a parser made with define-parser. Without a name, or with #f, it prints as #<procedure>.

Examples:
> (parser (lambda (in i) 'error) 'NEVER)

#<procedure:NEVER>

> (parser (lambda (in i) 'error))

#<procedure>

parser is a form, not a function, so it can’t be passed to apply or used as a value. A form makes the parser where its Run is written, so Racket’s compiler can see the Run, which makes parsing faster.

procedure

(parser? v) → boolean?

  v : any/c
returns #t if v is a Parser: one made by parser, or by one of the combinators.

procedure

(input-text in) → string?

  in : input?
produces the text of in, which a Run matches from the position it’s given. It is the text itself, not a copy.

procedure

(fail in i) → 'error

  in : input?
  i : exact-nonnegative-integer?
produces 'error, for a Run to fail with, and notes that the parse got to position i of in. If the parse fails and gets no further, parse says what it found there, as the library’s parsers do where they fail, so a Run can point at the character that’s wrong rather than where it began.

Examples:
; Parser
; matches two digits
> (define TWO-DIGITS
    (parser
     (lambda (in i)
       (define s (input-text in))
       (let loop ([j i])
         (cond [(= j (+ i 2))
                (matched (substring s i j) j)]
               [(and (< j (string-length s))
                     (char-numeric? (string-ref s j)))
                (loop (add1 j))]
               [else (fail in j)])))))
> (parse TWO-DIGITS "42")

"42"

> (parse TWO-DIGITS "4x")

parse: unexpected text "x" at line 1, column 2

procedure

(run p in i) → (or/c 'error matched?)

  p : Parser
  in : Input
  i : exact-nonnegative-integer?
runs p on in from position i, producing a Match. A Run uses run to run other parsers, passing its own input.

Examples:
; Parser -> Parser
; matches a digit n, then n of `p`, producing their list
> (define (counted p)
    (parser
     (lambda (in i)
       (let ([n (run (rx #rx"[0-9]") in i)])
         (if (symbol? n)
             'error
             (let loop ([k (string->number (matched-value n))]
                        [i (matched-end n)]
                        [vs '()])
               (if (zero? k)
                   (matched (reverse vs) i)
                   (let ([m (run p in i)])
                     (if (symbol? m)
                         'error
                         (loop (sub1 k)
                               (matched-end m)
                               (cons (matched-value m) vs)))))))))))
> (run (counted (lit "ab")) "x2ababab" 1)

(matched '("ab" "ab") 6)

> (parse (counted (lit "ab")) "3ababab")

'("ab" "ab" "ab")

> (parse (counted (lit "ab")) "2ababab")

parse: unexpected text "ab" at line 1, column 6

  expected: end of input
